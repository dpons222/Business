# Product

Use this folder for the reusable restaurant recommendation and implementation model.

## Files

- `recommendation-framework.md`: how to inspect a restaurant and select the right module.
- `solution-modules.md`: the current module menu and when each module fits.
- `solution-copy-deck.md`: reusable copy blocks for recommendations, outreach, and future demos.
- `personalization-rules.md`: what to personalize before outreach, after reply, and during a paid pilot.
- `personalized-demo-template.md`: template for future prospect-specific recommendation briefs.
- `personalized-demos/`: light recommendation/demo briefs for specific restaurants. Public visual routes should live in the demo app and use customer-facing copy.

## Product Principle

Use one diagnostic framework, then recommend one focused module per restaurant.

Do not assume the deliverable is a landing page. A landing page is only one module. The right first module should be based on the restaurant's public customer journey, visible gaps, operational fit, and likelihood that the owner can act on the recommendation.

## Public Demo Copy

When a prospect demo is deployed as a public route, write it as guest-facing copy for that restaurant.
Internal audit findings, pricing strategy, implementation notes, and recommendation labels belong in
the prospect package and outreach materials, not in the public page.
