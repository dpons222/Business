# 002 Restaurant Growth Systems Plan

## Experiment Question

Will local restaurants pay for a personalized recommendation and implementation package based on the most important visible gap in their customer journey?

## Decision

```text
Primary offer angle: Restaurant growth audit + one focused implementation module
Target market: Independent local restaurants with visible conversion, ordering, booking, catering, events, reputation, content, or retention gaps
Price test: $750 setup for one module
Optional add-on: $250/month for tracking review, updates, content support, or automation maintenance
Validation target: 20 qualified prospects
Success signal: 1 paid pilot, 2 serious sales calls, or 3-5 positive replies
Timebox: 14 days
```

## Hypothesis

Independent restaurants often have different bottlenecks. Some need a focused catering or private dining page. Others need their Google Business Profile links cleaned up, their online ordering path simplified, review responses systemized, weekly specials turned into reusable content, or lapsed guests reactivated.

A flexible recommendation offer should feel more relevant than a single fixed service because the pitch starts from the restaurant's actual situation.

## Recommendation Principle

Start with diagnosis, not a preset deliverable.

For each restaurant:

1. Inspect the public customer journey.
2. Identify the highest-leverage visible gap.
3. Match the gap to one implementation module.
4. Prepare a short recommendation and lightweight example.
5. Sell a fixed-scope pilot only after the owner shows interest.

## Solution Modules

- Catering or private dining inquiry page.
- Restaurant email/SMS promo automation.
- Google Business Profile, menu, and ordering link cleanup.
- Online ordering conversion audit.
- Event or private dining lead tracking system.
- Review response and reputation workflow.
- Weekly specials content automation.
- Birthday, loyalty, or lapsed-guest reactivation campaign.
- Restaurant website and menu cleanup package.
- Focused landing page or campaign page when that is the best fit.

## Scope

In scope:

- Define the flexible restaurant recommendation offer and price test.
- Create a diagnostic framework for choosing the right module per restaurant.
- Create prospect qualification criteria.
- Create restaurant outreach and follow-up scripts.
- Create discovery call questions.
- Create reusable product docs for solution modules and personalization.
- Create prospect tracking files.
- Prepare the experiment for a future first outreach batch.

Out of scope for this phase:

- Building demo app code.
- Researching real prospects.
- Sending outreach.
- Running ads.
- Managing reservations, delivery, point-of-sale, or ordering systems directly.
- Taking over full social media management.
- Replacing a restaurant's full website unless the recommendation clearly calls for a narrow cleanup package.
- Guaranteeing reservations, orders, leads, revenue, rankings, ratings, or campaign outcomes.

## 14-Day Validation Plan

Days 1-2:

- Finalize the flexible offer, diagnostic framework, outreach message, and qualification criteria.

Days 3-5:

- Build a list of 20 qualified restaurant prospects in one chosen market.
- For each restaurant, choose one likely module based on public evidence.

Days 6-8:

- Create 3-5 light personalized recommendations.
- Prepare exact outreach drafts and run the pre-send checklist.

Days 9-11:

- Send first outreach batch after review.
- Track replies, objections, and calls.

Days 12-14:

- Send follow-ups.
- Decide whether to sell a paid pilot, narrow to the strongest module, change restaurant segment, or stop.

## Success Criteria

Continue if:

- 1 paid pilot is secured, or
- 2 serious sales calls are booked, or
- 3-5 positive replies indicate interest in the personalized recommendation model.

Narrow if:

- One module clearly gets better replies than the others.
- Restaurants respond to the audit but only want one category of help.
- The flexible pitch creates interest but too much delivery complexity.

Revise if:

- Restaurants like the idea but object to price, timing, trust, or implementation scope.
- Owners want a lower-risk diagnostic before paying for implementation.
- Prospects prefer another module not currently listed.

Stop or change niche if:

- 20 qualified prospects produce no replies.
- Replies show no clear pain or willingness to pay.
- Interest only appears when the work is free or heavily discounted.

## Risks

- A broad offer can become vague if the recommendation is not specific.
- Restaurants have thin margins, so the recommendation must connect to a practical business action.
- Too many modules can create delivery complexity before demand is proven.
- Some restaurants rely on third-party platforms and may resist changes.
- Claims must avoid promising reservations, orders, revenue, rankings, ratings, or ad outcomes.

## Next Action

Research a first batch of 20 qualified restaurants in one market. For each prospect, assign the best-fit solution module and write a one-sentence recommendation before creating any demo.
