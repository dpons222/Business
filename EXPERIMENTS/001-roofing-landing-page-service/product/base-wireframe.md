# Base Wireframe

## Purpose

Reusable structural layout for a storm damage / roof inspection landing page.

This wireframe should be lightly personalized per prospect with company name, phone number, city, service area, and public trust signals.

## Layout Summary

```text
1. Sticky mobile call/action bar, if appropriate
2. Hero with CTA and trust proof
3. Urgency/problem section
4. Inspection offer section
5. Trust proof section
6. Process section
7. Services section
8. Lead form section
9. FAQ section
10. Final CTA section
```

## Section Rules

### Hero

- Must show the company name.
- Must show the primary CTA.
- Must show phone CTA.
- Must mention storm damage or roof inspection.
- Should include one local trust signal.

### Problem / Urgency

- Keep it educational, not fear-based.
- Do not imply every storm requires roof replacement.

### Inspection Offer

- Make the free inspection concrete.
- Use bullets or small cards.
- Explain what happens after the inspection.

### Trust Proof

- Use only real client proof.
- If proof is unknown, use placeholder labels in the base demo.
- Place proof before the form.

### Lead Form

- Keep form fields short.
- Phone should be prominent.
- Avoid insurance claim fields in the first version.

### FAQ

- Use short answers.
- Avoid legal, insurance, or guarantee-heavy claims.

## Design Notes

Visual style:

```text
Modern local service
Clean
Trustworthy
Mobile-first
Proof-heavy
Direct CTA hierarchy
```

Recommended UI patterns:

```text
Icon + short text trust cards
Compact testimonial card
Step cards for process
Accordion FAQ
Sticky call button on mobile, if it does not cover content
Short lead form
```

Avoid:

```text
Huge decorative hero
Dark disaster imagery
Overly trendy SaaS aesthetic
Thin low-contrast text
Hard-to-tap buttons
Long paragraphs
Too many CTA types
```
